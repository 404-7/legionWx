# 攻击骰子、武器时序与阶段计时

本轮补齐攻击流程和计时，浏览器与 Node 服务端使用相同实现。

- 普攻按「基础伤害 + N 个独立整数骰子」计算。守军、波次怪物、雇佣兵和国王均接入，不再使用连续均匀随机或怪物固定平均伤害。
- 已改为地图攻击字段优先，旧表格数值保留在 sheetStats；缺失原生基础字段仍显式记录为继承默认值或待核验项。
- 物编 `udp1` 控制攻击前摇，`ua1z × 0.25` 控制地图上的弹速。前摇随攻速调整，不再按攻击间隔的 60% 截断；目标离开射程、死亡或攻击者眩晕会取消前摇。
- 怪物攻击守军、追击到王城后攻击国王都经过前摇；远程普攻在弹道命中时结算。出手后攻击者死亡不清除已发射的弹道，目标死亡则丢弃该弹道。
- 近战、normal/instant 武器和显式零弹速武器不产生飞行延迟。弹射武器依次选择附近未命中的合法目标，飞到后再结算衰减伤害；弹道更新过程中产生的后续弹道不会丢失。
- 新生成的怪物攻击冷却从 0 开始，取消额外随机的 0.6–1.1 秒首次出手延迟。

## 原图计时

来源为原地图 `war3map.j`：

| 阶段 | 时间 |
|---|---|
| 首波准备 | 80 秒 |
| 普通下一波准备 | 40 + floor(将开始的波次 / 2) 秒 |
| 第 10、20 波后的 PK 准备 | 30 秒 |
| PK 胜负确定至发奖 | 2 秒 |
| PK 发奖后的结果展示 | 20 秒 |
| PK 后第 11、21 波准备 | 30 秒 |
| 第 31 波准备 | 60 秒，保留已有生存关流程 |

普通波的 240 秒自动漏怪和 PK 的 180 秒自动平局已移除。路口防卡、不可达目标脱离和追击控制继续生效，它们不会按整场战斗时长强制结算。

## 仍待核实

地图只保存覆盖值，没有附带完整 Warcraft 基础单位数据库。`hfoo`、`hrif` 的部分字段通过显式基础默认值补齐，其他缺失前摇继续使用 0.3 秒、缺失弹速继续使用原网页默认值；这些不是已经由原客户端验证的结果。

运行 `node scripts/audit-weapons341.cjs` 可生成 `data/legion341-weapons-audit.json`，逐个记录表格伤害、地图伤害字段、前摇与弹速来源（map / inherited-default / web-fallback）。近战无需弹道，其缺失弹速不影响攻击时序。表格与物编数值冲突、基础默认值及引擎转身/动画等差异继续保留为待核实项，不能宣称完整 1:1。

`tests/weapon-timing.test.cjs` 验证多骰子分布、全部显式字段导入、眩晕取消、飞行延迟、攻击者死亡、目标死亡、连续弹射及阶段时长。PK 奖励延迟与只发一次由 `tests/arena.test.cjs` 验证。
